## Findings addressed

1. **Installer branch selection could install the wrong configuration.** The
   old runbook switched to `master`, which lacks this NixOS work. Both initial
   and post-install clones now select an exact reviewed commit. The runbook
   explains that the commit must be published before erasing the old system.
2. **The activation helper accepted the current Pop!_OS host.** Its Linux,
   username, and hostname checks all matched. It now requires `/etc/NIXOS`
   before running any privileged rebuild command.
3. **Disk selection depended on NVMe numbering.** Disko now uses the actual
   SSD's verified model/serial identifier. The runbook still requires checking
   the physical disk before formatting.
4. **Desktop and terminal SSH could use different agents.** COSMIC enabled
   GCR while Home Manager enabled OpenSSH. GCR SSH is disabled, GNOME Keyring
   remains available for desktop credentials, and the personal SSH config
   explicitly selects Home Manager's agent on Linux.
5. **Login Fish lagged behind the configured user Fish.** NixOS and Home
   Manager now select the same Fish package. The stable completion generator
   remains disabled because it expects a file removed by newer Fish; native
   package completions remain available.
6. **Personal API credentials were exported into every interactive shell.**
   `with-anthropic` and `with-twilio` now load only their required credentials
   for an explicit command and reject missing or empty secrets. Existing
   sessions need a logout/login to discard previously inherited values.
7. **The cached Gitleaks binary did not follow dependency updates.** The
   scanner now checks the locked revision before reuse. The pre-commit hook
   uses the same resolver, which reads the lock file without importing the
   candidate source tree into the Nix store.
8. **A fresh desktop lacked the user's browsers.** Firefox and Google Chrome
   are now declared. The unfree allowlist is limited to Chrome and the NVIDIA
   packages required by this Pascal GPU.
9. **SSH and recovery documentation disagreed with the new key policy.** The
   ThinkPad uses its own Ed25519 key and OpenSSH agent. GPG handles Pass and
   signing; the primary GPG secret key need not be copied for SSH. The Mac's
   existing GPG SSH fallback remains until every destination is tested.
10. **The default Nix package lagged behind the latest release.** Both system
    profiles now use `nixVersions.latest` from the locked unstable input.

The earlier Codex installation changes are included: CLI defaults are stored
in `/etc/codex/config.toml`, user preferences stay writable, and `bubblewrap`
is available for the normal Linux sandbox. Codex runs as `bcmyers` without a
dedicated VM or account. See [Codex](codex.md), [credentials](ssh.md), and
[secrets](../secrets/README.md).

## Remaining installation checks

- The graphical Codex/ChatGPT app is not supplied for Linux by the current
  Nixpkgs `chatgpt` package. CLI installation is covered; NixOS desktop
  packaging and browser integration need separate validation.
- Native Mac and ARM builds cannot be established by x86_64 Linux evaluation
  alone. Build on those platforms before activating shared changes there.
- Physical NVIDIA/COSMIC login, Wi-Fi, audio, suspend, brightness, and battery
  behavior require tests on the actual NixOS installation. A VM cannot prove
  those hardware behaviors.
- Provision the permanent ThinkPad SSH key, local logins, age identity, GPG
  subkeys, and Password Store as described in the runbook. Runtime credentials
  are intentionally not restored by a Nix build. Unknown historical GitHub
  keys still need identification before revocation.
- The chosen LUKS layout needs a person to enter the passphrase after a full
  reboot. It does not provide unattended recovery after power loss.

These checks do not certify third-party packages or establish that no further
improvements are possible. They cover the declared configuration, builds,
and the tested installation path.
